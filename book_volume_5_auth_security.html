1. Authentication vs Authorization & The 401 vs 403 Distinction
📌 1.1 Definition & Distinction
  • Authentication (AuthN): "Who are you?" Verifying identity via credentials (email + password, OTP, OAuth). If identity cannot be proven ──▶ 401 Unauthorized (really means Unauthenticated).
  • Authorization (AuthZ): "What are you allowed to do?" Verifying permissions, roles, and ownership once identity is proven. If a logged-in user tries to delete another user's account ──▶ 403 Forbidden.
2. Password Hashing: bcrypt, Salt Rounds & Timing Attack Defense
📌 2.1 Why Plain Hashing (SHA256/MD5) is Broken

Standard cryptographic hashes like SHA-256 are designed to be fast (billions of hashes/sec for hardware data integrity). Attackers using GPUs can crack billions of plain SHA-256 passwords per second using rainbow tables. bcrypt is an adaptive, CPU-intensive, salt-based hashing algorithm designed specifically to be intentionally slow (Key Stretching).

3. JSON Web Tokens (JWT): Header, Payload, Signature & Bearer Tokens
📌 3.1 The 3 Parts of a JWT

A JWT is a compact, URL-safe means of representing claims to be transferred between two parties. It is composed of three Base64Url-encoded strings separated by dots: header.payload.signature.

🔬 Bio-Anatomy: The Cryptographic Anatomy of a JWT STATELESS AUTH
Part 1: Header (Red) ──▶ Base64Url({ "alg": "HS256", "typ": "JWT" })
Part 2: Payload (Purple) ──▶ Base64Url({ "id": "64b1...", "role": "admin", "exp": 1720000000 })
Part 3: Signature (Blue) ──▶ HMACSHA256(header + "." + payload, secretKey)
─────────────────────────────────────────────────────────────────────────────
⚠️ CRITICAL SECURITY RULE: The payload is ONLY Base64Url encoded, NOT ENCRYPTED!
Anyone can decode it at jwt.io. NEVER put passwords or sensitive credit cards in a JWT!
💻 3.2 Practical Code: JWT Authentication & Role Authorization Middleware
middleware/authMiddleware.jsProduction Pattern
const jwt = require("jsonwebtoken");
const User = require("../models/User");

// 1. Protect Middleware (Authentication Guard)
exports.protect = async (req, res, next) => {
    let token;
    if (req.headers.authorization && req.headers.authorization.startsWith("Bearer")) {
        token = req.headers.authorization.split(" ")[1];
    }

    if (!token) {
        return res.status(401).json({ success: false, message: "You are not logged in! Please log in to get access." });
    }

    try {
        // Verify token signature
        const decoded = jwt.verify(token, process.env.JWT_SECRET);

        // Check if user still exists in DB
        const currentUser = await User.findById(decoded.id);
        if (!currentUser) {
            return res.status(401).json({ success: false, message: "The user belonging to this token no longer exists." });
        }

        // Grant access & attach user to request object
        req.user = currentUser;
        next();
    } catch (err) {
        return res.status(401).json({ success: false, message: "Invalid or expired token!" });
    }
};

// 2. RestrictTo Middleware (Role-Based Access Control)
exports.restrictTo = (...roles) => {
    return (req, res, next) => {
        if (!roles.includes(req.user.role)) {
            return res.status(403).json({
                success: false,
                message: "Forbidden: You do not have permission to perform this action"
            });
        }
        next();
    };
};
4. Backend Vulnerabilities: NoSQL Injection, IDOR & Mass Assignment
📌 4.1 NoSQL Injection & Sanitization

Attackers pass MongoDB query operators like { "username": "admin", "password": { "$ne": null } } in the request body, bypassing authentication because password != null evaluates to true! Prevent with express-mongo-sanitize (which strips dollar signs $ from incoming payloads).

📌 4.2 Insecure Direct Object References (IDOR) & Ownership Guards

An attacker changes the URL from /api/jobs/101 to /api/jobs/102 to delete a job posted by someone else. Prevent by checking that job.postedBy.toString() === req.user._id.toString() or req.user.role === 'admin' before proceeding!

📌 4.3 Mass Assignment Defense

If you write User.create(req.body), an attacker can submit { "name": "Eve", "role": "admin" } and escalate privileges! Always filter input fields using a whitelist: const { name, email, password } = req.body;.
