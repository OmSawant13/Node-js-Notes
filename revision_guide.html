1. Variable Scopes & Temporal Dead Zone (TDZ)
🤔 1.1 Problem Kya Thi? (Why ES6 Introduced let & const)

ES5 tak JavaScript me sirf var keyword tha. var ke saath do bohot khatarnak problems thi:

  1. Accidental Re-declaration: Agar 500 lines ke code me galti se dubara var user = "amit" likh doge, toh JavaScript koi error throw nahi karta aur purana data overwrite kar deta hai.
  2. No Block Scope: var curly braces { ... } ko respect nahi karta. Loop ke baad bhi variable bahar zinda reh kar memory pollute karta hai!
snippet_var_vs_let.jsScope Problem Example
// ⚠️ Problem with var: No block scope & silent overwrite!
var role = "Junior Dev";
if (true) {
    var role = "Team Lead"; // Overwrites outer variable silently!
}
console.log(role); // Outputs: "Team Lead" (Outer variable corrupted!)

// ✅ Solution with let: Strict Block Scope!
let score = 50;
if (true) {
    let score = 99; // Lives only inside this { ... } block
}
console.log(score); // Outputs: 50 (Outer variable stays completely safe!)
🔍 var vs let/const Ka Post-Mortem (Surgical Code Dissection) VARIABLE SCOPING
var role = 'user'; if(true) { var role = 'admin'; }
1. The var Leak Bug: var function-scoped hota hai, block-scoped nahi. Curly braces { ... } ke andar var declare karne par bahar ka role silently overwrite ho jata hai (Security Bug).
let role = 'user'; if(true) { let role = 'admin'; }
2. Block Scope Isolation: let aur const curly braces { ... } ke block ke andar isolated rehte hain. Bahar ka role intact rehta hai aur memory leak nahi hoti.
💡 1.2 Hoisting & Temporal Dead Zone (TDZ) Explained with Code

• Hoisting: JavaScript code execute karne se pehle ek Memory Creation Phase chalata hai jisme saare variables aur functions ko scope ke top par memory allocate hoti hai. var ko undefined se initialize kar diya jata hai, jabki let aur const ko memory toh milti hai lekin unhe <uninitialized> chhod diya jata hai.
• Temporal Dead Zone (TDZ): Scope me enter hone se lekar let/const ke actual declaration line tak ka time period TDZ kehlata hai. Is doran variable access karne par JS turant ReferenceError phekta hai taaki bug execute hi na ho!

snippet_tdz_demo.jsTDZ Behavior
// ⚠️ var Hoisting gives undefined (Silent bug)
console.log(city); // Output: undefined
var city = "Mumbai";

// 🚫 let / const inside TDZ throws error immediately!
// 👇 TDZ for 'state' starts here
console.log(state); // 💥 ReferenceError: Cannot access 'state' before initialization!
let state = "Maharashtra"; // 👈 TDZ ends here!
🏢 Indian Real-Life Analogy: Society Notice Board vs Biometric Flat

• var: Society ka purana khula notice board — koi bhi aakar naya notice chipka kar purana overwrite kar deta hai (Silent Global Bug).
• let / const: Har resident ka personal flat with biometric lock — jab tak aap flat ke door {} ke andar sahi line pe unlock nahi karte, bahar se koi touch nahi kar sakta (Block Scope & TDZ Protection).

2. Callbacks, Promises & Async/Await (Zero to Hero)
🤔 2.1 Async Code Kyu Zaroori Hai? (The Synchronous Blocking Problem)

JavaScript Single-Threaded hai — iske paas sirf ek Call Stack hota hai. Matlab ek time par sirf ek hi line execute ho sakti hai.

Agar aap database se 50,000 records fetch karne ka kaam synchronous (blocking) karoge, toh jab tak DB se data nahi aayega (2 seconds), pura server freeze ho jayega aur baki 10,000 users ki requests line me atki rahengi!

snippet_blocking_vs_nonblocking.jsSynchronous Blocking Freeze
// ⚠️ BAD (Synchronous Blocking): Freezes the whole Node.js process!
console.log("User 1 requests profile");
// Simulating a heavy 3-second blocking task:
const freezeTill = Date.now() + 3000;
while (Date.now() < freezeTill) { /* CPU is blocked 100% */ }
console.log("User 1 profile loaded!");
console.log("User 2 request finally reached..."); // Waited 3 seconds unnecessarily!
📞 2.2 Callback Kya Hai Aur Callback Hell Kyu Hua?

Callback: Ek function ko dusre function me as an argument pass karna taaki jab async task (DB fetch / Timer) complete ho, toh wo function execute ho sake.

Callback Hell (Pyramid of Doom): Jab ek async kaam ke baad dusra, fir teesra kaam karna padta hai, toh code right side me triangle jaisa banne lagta hai (Inversion of Control & Hard to Debug).

snippet_callback_hell.jsCallback Hell (Pyramid of Doom)
// ⚠️ Callback Hell: Deep nesting makes error handling a nightmare!
fetchUser(101, function(user) {
    fetchUserCart(user.id, function(cart) {
        calculateBill(cart.items, function(bill) {
            processPayment(bill.amount, function(receipt) {
                sendInvoiceEmail(receipt.id, function(status) {
                    console.log("Done! But look at the horrible triangle nesting! 😵");
                });
            });
        });
    });
});
🤝 2.3 Promises: Inversion of Control Ka Solution

Promise ek JavaScript Object hai jo future me complete hone wale async task ka Trustable Contract hai. Iske 3 states hote hain:

• 1. Pending: Initial state (kaam abhi chal raha hai).
• 2. Fulfilled (Resolved): Kaam successfully ho gaya (triggers .then() callback).
• 3. Rejected: Kaam fail ho gaya / error aa gaya (triggers .catch() callback).

snippet_promise_creation.jsPromise Creation & .then() / .catch()
// ✅ Clean Promise Contract
const placeFoodOrder = new Promise((resolve, reject) => {
    const isRestaurantOpen = true;
    setTimeout(() => {
        if (isRestaurantOpen) {
            resolve({ orderId: 9042, item: "Paneer Butter Masala" }); // Fulfilled!
        } else {
            reject(new Error("Restaurant is closed right now!")); // Rejected!
        }
    }, 1000);
});

// Consuming the Promise:
placeFoodOrder
    .then((order) => console.log("Order Delivered 🎉:", order))
    .catch((err) => console.error("Order Failed ❌:", err.message));
🍔 Indian Analogy: Haldiram Food Token vs Live Order

• Synchronous (Blocking): Aap counter pe khade ho, jab tak Chhole Bhature ban nahi jate, cash counter kisi aur customer se order nahi lega (Puri line jam!).
• Promise (Non-Blocking): Counter ne aapko ek Token (Promise) de diya aur bola "Pending". Aap aage badh gaye. Jab food ready hoga (Fulfilled), screen pe number flash hoga aur aap .then() me jakar khana utha loge!

⚡ 2.4 Async / Await: Modern Clean Standard

async/await Promises ke upar likha gaya syntactic sugar hai jo async code ko clean synchronous jaisa dikhata hai with simple try/catch error handling:

snippet_async_await_clean.jsAsync/Await with try/catch
async function checkoutUserCart(userId) {
    try {
        const user = await fetchUser(userId);
        const cart = await fetchUserCart(user.id);
        const receipt = await processPayment(cart.total);
        console.log("Payment Success! Receipt ID:", receipt.id);
    } catch (err) {
        console.error("Checkout failed gracefully:", err.message);
    }
}

2. Synchronous Error Handling: Callback hell me har step par alag error check karna padta tha. try/catch block me agar kisi bhi await step par network error ya payment failure hui, toh execution turant catch block me jump kar jayega.
const user = await fetchUserById(userId);
3. Await Execution Pause: await JavaScript thread ko block kiye bina function ke execution ko tab tak pause karta hai jab tak database se user data resolve hokar na aa jaye. Result milte hi user constant me store hota hai.
const cart = await fetchCartByUserId(user.id);
4. Dependent Step: Kyunki cart fetch karne ke liye user.id chahiye, isliye ye step pehle wale step ke baad sequentially execute hota hai.
return receipt;
5. Promise Resolution: Yahan se returned value caller ko ek Promise.resolve(receipt) ke roop me milti hai.

3. Destructuring — Object & Array
🔴 3.1 Problem Kya Thi?

Pehle hum object ki values access karne ke liye baar baar user.name, user.age, user.city likhte the. 10 properties hongi toh 10 lines waste. Agar spelling galat ho toh undefined silently aata tha — koi error nahi!

3_object_destructuring.jsRename + Defaults + Nested
// ❌ OLD WAY — repetitive and error prone
const user = { name: 'Priya', age: 24, city: 'Pune', role: 'Dev' };
const name1 = user.name; const age1 = user.age; // tedious x 4

// ✅ Destructuring — one line, zero repetition
const { name, age, city } = user;

// Rename while destructuring: userId → id
const apiResponse = { userId: 101, userName: 'aarav_dev', status: 'active' };
const { userId: id, userName: username, role = 'viewer' } = apiResponse;
//             ↑ rename   ↑ rename    ↑ default value if key missing!
console.log(id, username, role); // 101 'aarav_dev' 'viewer'

// Nested Object Destructuring
const order = { id: 501, customer: { name: 'Rahul', city: 'Delhi' }, amount: 1499 };
const { customer: { name: custName }, amount } = order;
console.log(custName, amount); // 'Rahul' 1499

// Array Destructuring — position based
const scores = [98, 75, 62, 89];
const [first, second, , fourth] = scores; // skip 3rd with empty comma

// ⭐ Classic Interview: Swap without temp variable!
let a = 10, b = 20;
[a, b] = [b, a]; // a = 20, b = 10 ✅

// Real Express.js use — ye destructuring hi hai!
app.get('/users/:id', (req, res) => {
    const { id } = req.params;    // Object destructuring
    const { page = 1 } = req.query; // Destructuring with default!
});

4. Spread (...) & Rest (...) — Same Symbol, Opposite Job
🔴 4.1 Problem Kya Tha?

Object copy/merge ke liye Object.assign() aur Array merge ke liye concat() likhna padta tha. Aur functions mein variable arguments handle karna messy tha. ... ne dono problems ek hi symbol se solve kar diye.

📖 4.2 Spread — iterable ko "phailao"

Jab ... value ke right side pe assignment mein use ho — ye Spread hai. Object/array ko uske parts mein tod deta hai.

4_spread_rest.jsSpread + Rest Patterns
// ===== SPREAD =====

// 1. Immutable Object Update (Most used in Node.js + React)
const user = { name: 'Amit', age: 25, city: 'Mumbai' };
const updated = { ...user, age: 26, designation: 'Lead' };
// user.age is still 25 — original NEVER mutated ✅

// 2. Merge two objects (later key wins)
const defaults = { theme: 'dark', lang: 'en' };
const userPrefs = { lang: 'hi' };  // override lang
const config = { ...defaults, ...userPrefs }; // { theme:'dark', lang:'hi' }

// 3. Array merge + clone
const arr1 = [1, 2], arr2 = [3, 4];
const merged = [...arr1, ...arr2]; // [1, 2, 3, 4]

// 4. Spread into function args
const nums = [4, 18, 7];
console.log(Math.max(...nums)); // 18

// ===== REST =====

// 1. Rest in function — collect remaining args into array
function calcTotal(gst, ...prices) {
    const sub = prices.reduce((s, p) => s + p, 0);
    return sub + (sub * gst / 100);
}
calcTotal(18, 500, 300, 200); // (1000) + 18% = 1180

// 2. Rest in destructuring — extract specific, keep rest
const emp = { name: 'Kiran', id: 'E204', salary: 95000, dept: 'Eng' };
const { salary, ...publicProfile } = emp;
// salary is private. publicProfile = { name, id, dept } — salary gone! ✅
🔬 Anatomy: Spread vs Rest — Same Symbol, Different Context KEY DIFFERENCE
SPREAD ── Right side of = ── Expands one into many
const copy = { ...obj }; ─ Opens the object up
REST ─── Left side of = ── Collects many into one
const { x, ...rest } = obj; ─ Gathers remaining
function foo(...args) {} ─ All arguments → array
💼 Interview Q
"Spread aur Rest mein kya fark hai?" — Same ... symbol, but context decide karta hai kya karega!
🚨 Rule
Rest parameter hamesha function ki last position pe hona chahiye! foo(...a, b) = SyntaxError!
5. Arrow Functions — Short Syntax + Fixed `this`
🔴 5.1 Problem: Regular Functions Ka `this` Dhoka Deta Tha

JavaScript mein this ka value decide hota hai function kaise call hua — not where it was written. Regular functions mein this runtime pe change ho jaata tha, especially callbacks mein class ka context kho jaata tha.

5_arrow_functions.jsthis Binding + Syntax
// ❌ Regular Function in setTimeout — 'this' gets lost!
function Timer() {
    this.seconds = 0;
    setInterval(function() {
        this.seconds++; // 💥 'this' is NOT Timer here — it's undefined/Window!
    }, 1000);
}

// ✅ Arrow Function — LEXICAL 'this' (locked to definition scope)
function TimerFixed() {
    this.seconds = 0;
    setInterval(() => {
        this.seconds++; // ✅ 'this' correctly refers to TimerFixed!
    }, 1000);
}

// Arrow Syntax — from verbose to concise
const add = function(a, b) { return a + b; }; // regular
const add = (a, b) => { return a + b; };      // arrow full
const add = (a, b) => a + b;                    // implicit return ✅
const double = n => n * 2;                       // single param, no ()
const getUser = id => ({ id, createdAt: new Date() }); // return object: wrap in ()

// ⚠️ WHEN NOT TO USE Arrow Functions
const counter = {
    count: 0,
    // ❌ Arrow — 'this' is NOT counter, it's outer scope!
    increment: () => { this.count++; },
    // ✅ Regular method — 'this' correctly refers to counter
    decrement() { this.count--; }
};
🔬 Anatomy: Arrow vs Regular — this Binding INTERVIEW CRITICAL
Regular Function ── Dynamic this ── Decided at CALL TIME
obj.method() → this = obj
setTimeout(fn) → this = undefined (strict mode)
Arrow Function ── Lexical this ── Decided at DEFINITION TIME
Inherits this from surrounding scope — LOCKED forever
💼 Interview Q
"Arrow aur regular function mein kya fark hai?" → this binding! Arrow = lexical, Regular = dynamic.
⛔ No arguments + No new
Arrow ke paas apna arguments object nahi hota. Constructor bhi nahi bana sakte (new Arrow() → Error).

7. Closures — Function Remembers Its Birthplace
📖 7.1 Closure Kya Hai?

Jab ek inner function apne outer function ke variables ko tab bhi access kar sakta hai jab outer function ka execution khatam ho chuka ho — ye Closure hai. Inner function apne surrounding lexical scope ka reference memory mein rakhta hai.

7_closures.jsPrivate State + Real Backend Use
// makeCounter run hoke khatam ho jata hai...
function makeCounter() {
    let count = 0; // Private — bahar se directly access nahi kar sakte!

    return {
        increment() { count++; console.log(`Count: ${count}`); },
        getCount()  { return count; }
    };
}

const counter = makeCounter(); // khatam hua... lekin count yaad hai!
counter.increment(); // Count: 1
counter.increment(); // Count: 2
console.log(counter.count); // undefined — PRIVATE! ✅

// Real Node.js use: Middleware Factory (closures in Express!)
function requireRole(role) {           // outer function
    return function(req, res, next) {   // inner function (middleware)
        if (req.user?.role !== role) {    // 'role' from closure!
            return res.status(403).json({ error: 'Access Denied' });
        }
        next();
    };
}
// Usage:
app.delete('/admin/user', requireRole('admin'), deleteUserHandler);
// requireRole('admin') returns a middleware that "remembers" 'admin' via closure!
🔍 JavaScript Closures Ka Post-Mortem LEXICAL SCOPING
function makeCounter() { let count = 0; return () => ++count; }
1. Private State Encapsulation: count variable bahar se direct accessible nahi hai (private state). Inner arrow function apne parent function ke lexical scope ko memory me "band (close)" karke retain karta hai.
const counter = makeCounter(); counter();
2. Persistent Memory: makeCounter return hoke stack se nikal jata hai, lekin Heap memory me closure reference rehne ki wajah se har baar counter() call karne par incremented value milti hai (1, 2, 3...).
🔬 Anatomy: Closure Memory Lifecycle INTERVIEW CRITICAL
makeCounter() called ── Stack frame created with count = 0
Returns inner object → stored in heap as counter
makeCounter stack frame destroyed ✗ (done)
BUT: inner functions hold [[Environment]] reference to outer scope
└─ count survives in heap as long as counter object exists!

8. map / filter / reduce — Array Ki Power Trio
🔴 8.1 Problem: for loops se data transform karna messy tha

Array transform karne ke liye hum for loop likhte, nayi array manually push karte — verbose aur error prone. ES6 ne 3 declarative alternatives diye jo shorter, readable, aur immutable hain.

📖 map() — Har Element Transform Karo (Same Size)
8_map_filter_reduce.jsArray Power Trio
const employees = [
    { name: 'Sneha', salary: 60000, dept: 'HR' },
    { name: 'Ravi',  salary: 85000, dept: 'Eng' },
    { name: 'Ankit', salary: 72000, dept: 'Eng' }
];

// ===== MAP — Transform every element, returns SAME SIZE array =====
const withHike = employees.map(emp => ({ ...emp, salary: emp.salary * 1.1 }));
// Original employees array UNCHANGED ✅

// ===== FILTER — Keep matching elements, returns SMALLER/EQUAL array =====
const engTeam = employees.filter(emp => emp.dept === 'Eng');
// [{ name:'Ravi'... }, { name:'Ankit'... }]

// ===== REDUCE — Fold everything into ONE value =====
const totalPayroll = employees.reduce((acc, emp) => acc + emp.salary, 0);
// 60000 + 85000 + 72000 = 217000

// POWER MOVE: Chain all three!
const engPayrollAfterHike = employees
    .filter(emp => emp.dept === 'Eng')
    .map(emp => ({ ...emp, salary: emp.salary * 1.1 }))
    .reduce((acc, emp) => acc + emp.salary, 0);

🌊 1.3 Streams & Backpressure Management

Jab aapko 5 GB ki video ya 1 crore database records transfer karne hote hain, toh pura file RAM me load karne par JavaScript heap out of memory error aayega aur server crash ho jayega.

• Streams: Data ko 64 KB ke chhote Chunks me tod kar ek jagah se dusri jagah pipe karte hain.
• 4 Types of Streams:
  1. Readable Stream: Jahan se data padha jata hai (e.g. fs.createReadStream, HTTP req).
  2. Writable Stream: Jahan data likha jata hai (e.g. fs.createWriteStream, HTTP res).
  3. Duplex Stream: Jo padh aur likh dono sake (e.g. TCP Net Socket).
  4. Transform Stream: Jo data aane par usse modify/compress kare (e.g. zlib.createGzip()).
• Backpressure: Jab reader tezi se chunks bhej raha ho aur writer slow ho, toh internal buffer bhar jata hai. .pipe() ya stream.pipeline() reader ko automatically pause kar deta hai aur writer ke drain hone par resume karta hai!

const http = require('http');

const server = http.createServer((req, res) => {
    const { method, url } = req;

    if (method === 'POST' && url === '/api/order') {
        const bodyChunks = [];

        // 1. Listen to incoming binary chunks:
        req.on('data', (chunk) => {
            bodyChunks.push(chunk);
        });

        // 2. When all TCP packets finish, assemble & parse:
        req.on('end', () => {
            const rawBody = Buffer.concat(bodyChunks).toString('utf-8');
            const parsedData = JSON.parse(rawBody);

            // 3. Send HTTP Status 201 + JSON Response:
            res.writeHead(201, { 'Content-Type': 'application/json' });
            res.end(JSON.stringify({ status: 'Success', orderId: 108, item: parsedData.dish }));
        });
    } else {
        res.writeHead(404, { 'Content-Type': 'text/plain' });

});

        res.writeHead(200, { 'Content-Type': 'application/json' });
        return res.end(JSON.stringify({ status: 'Healthy', uptime: process.uptime() }));
    }

    // POST /api/echo
    if (method === 'POST' && url === '/api/echo') {
        let chunks = [];
        req.on('data', c => chunks.push(c));
        req.on('end', () => {
            const body = Buffer.concat(chunks).toString();
            res.writeHead(200, { 'Content-Type': 'application/json' });
            res.end(JSON.stringify({ received: JSON.parse(body) }));
        });
        return;
    }

    res.writeHead(404, { 'Content-Type': 'application/json' });
    res.end(JSON.stringify({ error: 'Route Not Found' }));
});

// 2. Route-Specific Auth Guard Middleware:
function requireAuth(req, res, next) {
    const token = req.headers['authorization'];
    if (token === 'Bearer secret-token-123') {
        next(); // User allowed to proceed!
    } else {
        res.status(401).json({ error: 'Unauthorized: Access Token Invalid or Missing' });
    }
}

// 3. Protected Route using Auth Guard:

    res.json({ secretData: "Welcome to the VIP Admin Dashboard!" });
});

// 4. Global 4-Argument Error Handler (err, req, res, next):
app.use((err, req, res, next) => {
    console.error("Global Error Caught:", err.message);
    res.status(err.status || 500).json({ error: err.message });
});

// ===== STEP 2: AUTH MIDDLEWARE — Token Verify karo =====
function authenticateToken(req, res, next) {
    const authHeader = req.headers['authorization'];
    // Format: "Bearer eyJhbGci..."
    const token = authHeader && authHeader.split(' ')[1]; // "Bearer" ke baad ka part

    if (!token) return res.status(401).json({ error: 'Token required' });

    try {
        const decoded = jwt.verify(token, process.env.JWT_SECRET);
        req.user = decoded; // { userId: 101, role: 'admin', iat: ..., exp: ... }
        next(); // Token valid! Aage jaao.
    } catch (err) {
        return res.status(401).json({ error: 'Invalid or expired token' });
    }
}

// ===== STEP 3: PROTECTED ROUTES — Middleware lagao =====

function errorHandler(err, req, res, next) { // 4 params = error middleware!
    console.error(`[ERROR] ${err.message}`, { url: req.url, method: req.method });

    const statusCode = err.statusCode || 500;
    const message   = err.message   || 'Internal Server Error';

    res.status(statusCode).json({
        success: false,
        error:   message,
        // Stack trace only in dev — never in production!
        ...(process.env.NODE_ENV === 'development' && { stack: err.stack })
    });
}

Q 01 ES6 • TDZ

What is Temporal Dead Zone (TDZ) and why did ES6 introduce it?

Ans: TDZ is the period between entering block scope and variable declaration. Unlike var which initialized to undefined (causing silent bugs), let and const stay uninitialized. Accessing them inside TDZ throws a runtime ReferenceError.
Q 02 ES6 • Functions

Why can't Arrow Functions be used as Object methods or Constructors?

Ans: Arrow functions do not bind their own dynamic this (they lexically inherit this from outer scope) and lack internal [[Construct]] method and .prototype property. Calling new ArrowFunc() throws a TypeError.
Q 03 ES6 • Microtasks

What is the difference between Microtask Queue and Macrotask Queue?

Ans: Microtask Queue has strict higher priority. Promise.then(), Promise.catch(), and process.nextTick() run immediately after current synchronous script completes, before the engine picks next Macrotask (such as setTimeout).
Q 04 ES6 • Memory

Shallow Copy vs Deep Copy in JavaScript — how do they differ?

Ans: Spread { ...obj } creates a shallow copy (top-level values cloned, nested references shared). For a deep copy, use structuredClone(obj) or JSON.parse(JSON.stringify(obj)).
Q 05 ES6 • Closures

What is a Closure and where is it used in Node.js backend architecture?

Ans: A closure is a function bundled with references to its surrounding lexical scope. Used in Node for data encapsulation, middleware factories (e.g. express.urlencoded() returning configured middleware), and memoization caches.
Q 06 Node • Concurrency

If Node.js is single-threaded, how does it handle thousands of concurrent requests?

Ans: JS execution stack is single-threaded, but Node offloads blocking I/O (file system, DNS, crypto) to the libuv C threadpool (default 4 threads) or OS kernel epoll/kqueue. When I/O completes, libuv pushes callback to event loop queue without blocking main JS thread.
Q 07 Node • Event Loop

List the 6 phases of the Node.js Event Loop in their exact order.

Ans: 1. Timers ➔ 2. Pending Callbacks ➔ 3. Idle/Prepare ➔ 4. Poll ➔ 5. Check ➔ 6. Close Callbacks.
Q 08 Node • Microtasks

What happens if `process.nextTick()` is called recursively in Node.js?

Ans: Causes I/O Starvation. Because nextTick queue is drained completely before Event Loop can move to next phase, recursive nextTicks trap engine in infinite loop, blocking Timers and I/O!
Q 09 FS • Safety

Why is `fs.readFileSync()` forbidden in high-concurrency production servers?

Ans: Because JS runs on single main thread. readFileSync halts entire thread until hard drive finishes reading, freezing every other incoming user request.
Q 10 Streams • Flow

What is Stream Backpressure and how does `.pipe()` resolve it?

Ans: Backpressure happens when readable stream emits data faster than writable stream can write to disk. .pipe() pauses readable stream when internal buffer is full and resumes when drain event fires.
Q 11 Express • Error Handler

Why must an error-handling middleware explicitly define exactly 4 parameters `(err, req, res, next)`?

Ans: Express checks handler arity via fn.length. If fn.length === 4, Express registers it as an Error Middleware and only invokes it when next(err) is called or an error throws.

Why must `/jobs/new` be placed before `/jobs/:id` in route definitions?

Why must `package-lock.json` be committed to Git repositories?

Ans: package.json allows semver ranges (like ^5.0.0), which means two developers running npm install on different days might get different minor/patch versions. package-lock.json pins the exact dependency tree down to the exact commit and cryptographic hash, ensuring 100% reproducible builds across all machines and production servers.

What is the key difference between CommonJS (`require`) and ES Modules (`import`)?

Ans: CommonJS (require() / module.exports) loads synchronously at runtime (can be used inside if-blocks). ES Modules (import / export) are parsed and evaluated asynchronously and statically before code executes, enabling dead-code elimination (tree-shaking).
Q 15 REST • HTTP Methods

What is the core difference between `PUT` and `PATCH` HTTP methods?

Ans: PUT replaces the entire resource entity (if a field is omitted in the payload, it will be wiped or overwritten with null/defaults). PATCH performs a partial update, modifying only the specific fields provided in the request body while leaving other fields untouched.
Q 16 HTTP • Status Codes

What is the difference between 401 Unauthorized and 403 Forbidden?

Ans: 401 Unauthorized = Authentication failure (the server doesn't know who you are; invalid/missing token). 403 Forbidden = Authorization failure (the server knows who you are, but you don't have permission/roles to access this resource).
Q 17 Express • Body Parsing

What does `express.json()` do under the hood, and what happens if you forget it?

Ans: Under the hood, it intercepts incoming request streams with Content-Type: application/json, buffers the incoming byte chunks, parses the raw JSON string via JSON.parse(), and mounts the resulting JS object onto req.body. If omitted, req.body remains undefined.
Q 18 Express • Data Extraction

When should you use `req.params` vs `req.query` vs `req.body`?

Ans: req.params identifies a specific resource in the URL path (e.g. /jobs/:id). req.query is for filtering, sorting, and pagination via optional key-value URL query strings (e.g. /jobs?role=dev&page=2). req.body holds large or sensitive payloads sent in POST/PUT/PATCH requests (e.g. user registrations, form submissions).
Q 19 Express • Middleware

What happens if a custom middleware neither calls `next()` nor sends a response?

Ans: The HTTP request pipeline hangs indefinitely in pending state. The client browser or API consumer will wait until its internal timeout threshold expires (e.g. 2 minutes) and then throw a 504 Gateway Timeout or ERR_EMPTY_RESPONSE.
Q 20 Security • JWT

What is a JWT (JSON Web Token) and what are its 3 parts?

Ans: A JWT is a compact, URL-safe, stateless token for securely transmitting claims between parties. Its 3 dot-separated base64url-encoded parts are: Header (algorithm & token type), Payload (user claims like userId, role, expiration), and Signature (hash of Header + Payload signed with a secret key to prevent tampering).
Q 21 Security • Auth Headers

Where and how should a JWT token be transmitted from client to server?

Ans: In the HTTP Authorization request header using the standard Bearer scheme: Authorization: Bearer <token>. On the server, middleware extracts it with req.headers.authorization?.split(' ')[1] and verifies it via jwt.verify(token, SECRET).
Q 22 Architecture • MVC

What is the MVC Architecture pattern and why is it preferred over giant route files?

Ans: MVC enforces Separation of Concerns: Model manages raw data and database schemas, View handles UI templates / presentation (or client JSON), and Controller contains the core business logic. It prevents bloated 1000-line app.js files, enables independent unit testing, and allows team collaboration without merge conflicts.
Q 23 SSR • EJS Tags

What is the difference between `<%= %>`, `<%- %>`, and `<% %>` in EJS?

Ans: <%= val %> outputs HTML-escaped text (safe against XSS attacks). <%- val %> outputs raw, unescaped HTML. <% jsCode %> executes pure control-flow JavaScript (loops, if-conditions) without outputting any text to the template.
Q 24 Security • CORS

What is CORS and why do browsers block requests by default?

Ans: Cross-Origin Resource Sharing is a browser security mechanism based on the Same-Origin Policy. It prevents malicious websites (e.g. evil.com) from making unauthorized AJAX requests to your backend API (api.bank.com) using a user's saved cookies/credentials. Express uses the cors package to set Access-Control-Allow-Origin headers allowing trusted origins.
Q 25 Security • Helmet

Why is `helmet` middleware considered mandatory for production Express apps?

Ans: helmet() automatically sets 15+ HTTP security headers, including hiding X-Powered-By: Express (preventing attackers from identifying server technology), enforcing Strict-Transport-Security (HSTS), and blocking XSS with X-Content-Type-Options: nosniff.
Q 26 Production • Env Security

Why must `.env` files NEVER be committed to Git and how does `dotenv` load them?

Ans: .env stores high-security secrets (database passwords, JWT secret keys, API credentials). If committed to GitHub, bots scan and exploit them immediately. dotenv.config() reads the local .env file on startup and injects key-value pairs into Node's global process.env object.
Q 27 Express • Error Handling

How does a Global Error Handler work and why must it be registered LAST in Express?

Ans: When any route or middleware passes an error via next(err) or throws in synchronous code, Express skips all standard middleware and jumps directly to the 4-parameter error handler (err, req, res, next). It must be registered last because Express executes middleware in strict linear registration order.
Q 28 ES6 • Higher Order Functions

How do `map`, `filter`, and `reduce` differ in JavaScript array transformations?

Ans: map() transforms every element 1:1 and returns a new array of the same length. filter() selects elements matching a boolean predicate and returns a subset array. reduce() folds/aggregates all array elements into a single accumulated output value (number, object, array). None of them mutate the original array.
Q 29 Node • Streams vs Buffer

Why should you use `fs.createReadStream()` instead of `fs.readFile()` for files > 100MB?

Ans: fs.readFile() loads the entire file into RAM at once. If 50 users request a 200MB file simultaneously, memory spikes to 10GB, crashing the Node.js process with an Out of Memory (OOM) fatal error. fs.createReadStream() reads the file in tiny 64KB chunks and streams them on the fly, keeping memory usage constant at ~64KB.
Q 30 Express • REST Best Practice

Why is `res.status(201).json({ success: true, data })` standard practice in REST APIs?

Ans: It provides explicit HTTP status code semantics for API clients (201 Created vs default 200 OK) while returning a predictable, consistent envelope format (success flag, data payload, optional message) that frontend clients and mobile apps can reliably parse.
